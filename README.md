# Expo Native Glasses Template

**Project Name:** Expo Native Glasses Template  
**Description:** A production-ready boilerplate for building Meta smart glasses apps (or any Android app requiring custom native code) using Expo Dev Client + custom Kotlin native modules.

This template solves the "hard part" of Expo development: bridging custom native Android code while keeping the benefits of the Expo managed workflow. It includes a pre-configured native module bridge with a working ping/pong example.

## 🚀 What's Included

*   **Expo SDK 54** (Latest stable)
*   **Custom Native Module Bridge:** A pre-wired Kotlin module (`GlassesModule.kt`) connected to React Native.
*   **NDK Configuration:** Pre-configured `build.gradle` to avoid common NDK version mismatch crashes (set to NDK 27 for RN 0.76+).
*   **Native Source Backup:** A `native-src/` folder containing your custom Kotlin files, so they aren't lost when you run `prebuild --clean`.

## 🛠 Prerequisites

Before you start, ensure you have:

*   **Node.js** (LTS version recommended)
*   **Android Studio** (with Android SDK and NDK installed)
*   **Java Development Kit (JDK) 17** (Required for React Native 0.76+)
*   **Expo CLI:** `npm install -g expo-cli`

## 📦 Setup Instructions

Follow these steps to get the app running on your device in under 10 minutes.

### 1. Clone the Repository
```bash
git clone https://github.com/qcornell/expo-native-glasses-template.git
cd expo-native-glasses-template
```

### 2. Install Dependencies
```bash
npm install
```

### 3. Generate Native Projects
This command generates the `android/` and `ios/` folders based on the Expo config.
```bash
npx expo prebuild
```

### 4. Restore Custom Native Code
Because `prebuild` generates a fresh Android project, you must copy the custom Kotlin files into place.

**Copy the files from `native-src/` to the Android source directory:**

*   **Source:** `native-src/GlassesModule.kt`
*   **Destination:** `android/app/src/main/java/com/anonymous/DappilyDirector/GlassesModule.kt`

*   **Source:** `native-src/GlassesPackage.kt`
*   **Destination:** `android/app/src/main/java/com/anonymous/DappilyDirector/GlassesPackage.kt`

*   **Source:** `native-src/MainApplication.kt`
*   **Destination:** `android/app/src/main/java/com/anonymous/DappilyDirector/MainApplication.kt`
    *(Overwrite the existing MainApplication.kt)*

> **Note:** If you change the package name in `app.json`, you will need to update the `package` declaration at the top of these Kotlin files and move them to the corresponding folder structure.

### 5. Run on Android
Connect your Android device (USB debugging enabled) or start an emulator.

```bash
npx expo run:android
```

This will:
1.  Compile the native Android project (including your Kotlin module).
2.  Install the development build on your device.
3.  Start the Metro bundler.

## 📂 Folder Structure

*   **`App.tsx`**: Main entry point. Contains the React Native code calling the native module.
*   **`native-src/`**: **IMPORTANT.** Contains your custom Kotlin files. Always edit files here or copy them back here after modifying them in `android/`, so they are safe from `prebuild --clean`.
    *   `GlassesModule.kt`: The actual native logic (e.g., Bluetooth, Hardware access).
    *   `GlassesPackage.kt`: Registers the module with React Native.
    *   `MainApplication.kt`: The Android entry point, modified to load your package.
*   **`android/`**: Generated by Expo. **Do not treat this as permanent.** It can be regenerated at any time.

## 🧩 How It Works

1.  **JavaScript Side:** `App.tsx` imports `NativeModules` and calls `NativeModules.GlassesModule.ping()`.
2.  **Bridge:** React Native sends this call to the Android layer.
3.  **Native Side:** `GlassesModule.kt` receives the call, executes the `ping()` function, and returns a Promise resolving to `"Pong from Android Native! 👓"`.
4.  **Result:** The app displays the response on the screen.

## ⚠️ Troubleshooting

*   **"Cannot read property 'ping' of null"**: This means the native module isn't loaded. Did you copy the files from `native-src/` to `android/...` after running prebuild? Did you rebuild the app with `npx expo run:android`?
*   **NDK/C++ Crashes**: Ensure your `android/build.gradle` has `ndkVersion = "27.1.12297006"` (or matching your RN version). This template handles this, but `prebuild` might reset it if not configured in `app.json` plugins (future improvement).
